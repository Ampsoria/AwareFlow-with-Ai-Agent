# Weekly Summary — AwareFlow

## สัปดาห์ 5–11 ตุลาคม 2026

### วันอังคารที่ 6 ตุลาคม 2026

วันนี้พัฒนาระบบอบรม Security Awareness ตั้งแต่โครงสร้างระบบและฐานข้อมูล การทำงานของ AI Agent ไปจนถึงการอ่านบทเรียนและทำข้อสอบบนเว็บ พร้อมปรับหน้าตาให้ใช้สีองค์กร

### งานที่ทำเสร็จ

#### 1. โครงสร้างระบบและกระบวนการอบรม

- ออกแบบและจัดทำเอกสาร architecture, contracts และ handoff ตาม `FLOW.md`
- พัฒนาระบบด้วย Python, Streamlit และ SQLite แยกส่วนงานแอปพลิเคชัน ฐานข้อมูล โมเดล PDF และการส่งอีเมล
- จัดทำ migrations สำหรับโครงสร้างหลัก การป้องกันคำสั่งซ้ำ การตั้งค่าแอป และประวัติการเรียกเครื่องมือของ Agent
- รองรับการสร้างรอบ สร้างร่าง ขอแก้ไข อนุมัติ เผยแพร่ มอบหมายผู้เรียน ทำข้อสอบ และรายงาน
- เก็บเนื้อหาเป็นเวอร์ชัน โดยตรึงฉบับบทเรียน ข้อสอบ และข้อมูลผู้รับเมื่อเผยแพร่
- เพิ่มรายงาน CSV/PDF การตั้งเวลางาน และ outbox สำหรับ Email Preview/SMTP

#### 2. AI Agent และการเชื่อมต่อโมเดล

- เปลี่ยนส่วนสร้างบทเรียนให้เป็น Agent ที่ให้โมเดลเลือกเครื่องมือตามเป้าหมายและผลที่ได้รับ
- เครื่องมือประกอบด้วย ค้นแหล่งข้อมูล เขียนหรือแก้บทเรียน ตรวจร่าง ส่งให้คนตรวจ และขอข้อมูลเพิ่มเติม
- จำกัดจำนวนขั้นตอน การค้น และการสร้างร่าง พร้อมบันทึกประวัติเครื่องมือและรองรับการ retry
- การอนุมัติ เผยแพร่ และส่งอีเมลยังเป็นคำสั่งจากผู้ใช้ ไม่ใช่เครื่องมือที่ Agent เรียกเอง
- รองรับ OpenAI, OpenAI-compatible สำหรับ LM Studio/vLLM, Ollama, Claude และ Gemini รวมถึงจุดเชื่อมต่อโมเดลขององค์กร
- เพิ่มตัวอย่างการตั้งค่า provider, เอกสาร `PROVIDERS.md` และคำสั่ง `check-llm`
- ผู้ใช้เลือกว่าจะทดลอง Gemini ก่อน ส่วนโปรแกรมและ endpoint ของเครื่องที่พี่เลี้ยงใช้รันโมเดลยังไม่ทราบ

#### 3. การสั่งงานด้วย Prompt

- เพิ่มปุ่ม **เขียน Prompt ใหม่** ในหน้ารอบอบรม
- แสดงช่อง Prompt ให้เห็นชัด และรองรับการพิมพ์หัวข้อหรือความต้องการเอง
- อธิบายว่ารายการรอบเดิมไม่ใช่รายการหัวข้อที่จำกัดให้เลือก
- นำค่าเริ่มต้น Phishing ออกจากฟอร์มสร้างรอบใหม่
- หากไม่กรอกหัวข้อย่อหรือคำค้น ระบบใช้ข้อความจาก Prompt เป็นค่าเริ่มต้น

#### 4. เนื้อหาบทเรียนและ PDF

- ปรับคำสั่งสร้างบทเรียนให้มีรายละเอียดเพิ่มขึ้น ตั้งเป้าประมาณ 1,500–1,800 ตัวอักษรเมื่อหลักฐานเพียงพอ
- เน้นสถานการณ์ตัวอย่าง เหตุผล สัญญาณเตือน วิธีตอบสนอง และข้อปฏิบัติที่นำไปใช้ได้
- ขยายเนื้อหาตัวอย่างสาธิต และปรับข้อสอบให้อ้างอิงหัวข้อในบทเรียนอย่างสอดคล้องกัน
- จัด PDF ใหม่ให้มีหัวเรื่อง กรอบสถานการณ์ หัวข้อย่อย ข้อปฏิบัติ แหล่งอ้างอิง และเลขหน้า
- คงเป้าหมายหนึ่งหน้า A4 และขนาดตัวอักษรที่อ่านง่าย หากเนื้อหาล้นจะคืนข้อผิดพลาดให้ Agent แก้ ไม่ตัดข้อความทิ้ง
- เรนเดอร์และตรวจภาพ PDF ทั้งตัวอย่างปกติและกรณีเนื้อหายาวพร้อมสามแหล่งอ้างอิง
- อัปเดตตัวอย่าง `output/pdf/demo-lesson.pdf`; PDF ของเวอร์ชันที่บันทึกไว้ก่อนหน้านี้ไม่ได้ถูกเขียนทับ

#### 5. หน้าผู้เข้าอบรม

- เพิ่มบทอ่านเป็นข้อความในหน้า **ข้อสอบของฉัน** ให้ผู้ใช้เรียนบนเว็บได้โดยตรง
- แสดงสถานการณ์ เนื้อหา ข้อปฏิบัติ และแหล่งอ้างอิง ก่อนส่วนแบบทดสอบด้านล่าง
- ยังคงมีปุ่มดาวน์โหลดบทเรียน PDF
- ใช้เนื้อหาจากเวอร์ชันที่มอบหมายให้ผู้ใช้ ซึ่งตรงกับฉบับ PDF และรองรับรอบเดิมด้วย
- ส่งข้อมูลบทอ่านผ่าน allowlist โดยไม่ส่ง answer key หรือข้อมูลภายในของ Agent มาด้วย

#### 6. หน้าตาเว็บไซต์และสีองค์กร

- เปลี่ยนฟอนต์เว็บเป็น **Noto Sans Thai** และเก็บไฟล์ฟอนต์พร้อมใบอนุญาตไว้ในโปรเจกต์
- เพิ่มไฟล์ WOFF2 สำหรับเว็บและเปิดการให้บริการไฟล์ static
- ตั้งสีหลักเป็น **`#CF000D`** ใช้พื้นขาวและเทาอ่อน
- เปลี่ยนอีโมจิในแบรนด์เป็น SVG และเพิ่มไอคอนในเมนูและปุ่มหลัก
- ปรับ sidebar เมนูที่เลือก การ์ดตัวเลข ฟอร์ม ระยะห่าง และความกว้างของหน้าบทอ่าน
- ตรวจหน้าผู้ดูแลและผู้เรียนผ่านเบราว์เซอร์ และเริ่มเว็บหลักใหม่เพื่อโหลดการตั้งค่าฟอนต์
- บันทึกภาพตัวอย่างไว้ที่ `output/awareflow-brand-dashboard.png` และ `output/awareflow-brand-learner.png`

#### 7. การเพิ่มอีเมลผู้รับ

- ตรวจสอบและอธิบายวิธีใช้ฟีเจอร์ที่มีอยู่แล้ว: **ผู้ใช้และตั้งค่า → ผู้ใช้ → อีเมลทดสอบ** แล้วเพิ่มสมาชิกเข้ากลุ่มของรอบอบรม
- ยืนยันว่าควรเพิ่มหรือแก้อีเมลก่อนเผยแพร่ เพราะอีเมลผู้รับจะถูกตรึงไว้กับ assignment เมื่อเผยแพร่
- การตอบคำถามส่วนนี้ไม่ได้เพิ่มฟีเจอร์ส่งอีเมลใหม่หรือส่งอีเมลจริง

### การตรวจสอบและผลทดสอบ

- หลังเพิ่มบทอ่านบนเว็บ: ชุดทดสอบทั้งหมด **76 รายการผ่าน** ครอบคลุม core, integrations, Agent, providers, PDF และ UI
- หลังปรับธีมครั้งสุดท้าย: รันทดสอบ UI ที่เกี่ยวข้อง **3 รายการผ่าน** ไม่ได้รันทั้ง 76 รายการซ้ำหลังการแก้ธีม
- ตรวจ workflow ผ่าน UI tests ตั้งแต่สร้างรอบ แก้ไข อนุมัติ เผยแพร่ ทำข้อสอบ และสร้างรายงาน
- ตรวจ PDF หนึ่งหน้า การรองรับเนื้อหาที่ยาวขึ้น การปฏิเสธกรณีล้นหน้า และการไม่ใส่ข้อสอบลงในบทอ่าน PDF
- ตรวจเว็บจริงฝั่งผู้ดูแลและผู้เรียน และยืนยันว่าเว็บหลักให้บริการไฟล์ฟอนต์ WOFF2 ได้สำเร็จ
- การทดสอบ provider ใช้ mock/fake transport; ยังไม่ได้ยืนยันผลกับ API ของโมเดลจริง

### สถานะและงานที่ยังต้องดำเนินการต่อ

- เว็บที่ตรวจล่าสุดยังใช้ **Mock Agent / Mock Search** ซึ่งเป็นข้อมูลและพฤติกรรมจำลอง
- ต้องตั้งค่า Gemini หรือ provider ที่เลือกใน `.env` แล้วทดลองสร้างบทเรียนด้วยโมเดลจริง
- หากต้องการข้อมูลจากเว็บจริง ต้องตั้งค่า search provider เพิ่มด้วย
- หากจะใช้โมเดลจากเครื่องพี่เลี้ยง ต้องทราบโปรแกรมที่ใช้ รูปแบบ API และ endpoint ก่อน
- การส่งอีเมลจริงต้องตั้งค่า SMTP และรายชื่อผู้รับที่อนุญาต ปัจจุบันยังไม่ได้ทดสอบส่งอีเมลจริง
- การเข้าสู่ระบบยังเป็นตัวเลือกบัญชีสาธิต ไม่ใช่ระบบยืนยันตัวตนสำหรับใช้งานจริง
- รูปแบบ PDF ใหม่มีผลกับฉบับที่สร้างใหม่ ส่วนบทอ่านบนเว็บและธีมใหม่ใช้กับรอบเดิมได้
